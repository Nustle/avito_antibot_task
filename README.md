## О задаче
**Контекст**. Существуют внешние сервисы, которые автоматически собирают данные из объявлений Авито: отслеживают цены, составляют сводки по категориям и выгружают контакты продавцов.

Команда Антибота подготовила выборку с разметкой на основе известных источников трафика. Положительный класс представлен трафиком нескольких сервисов автоматизированного сбора данных, отрицательный — трафиком, отнесённым к человеческому. 

Твоя задача — по событиям внутри суточного окна построить модель, которая присваивает каждой ```cookie_id``` оценку от 0 до 1: чем выше значение, тем вероятнее принадлежность к положительному классу.

Target: 1 — трафик известных сервисов сбора данных; 0 — трафик, отнесённый к человеческому.

### Данные
Тебе доступны файлы:
- ```data/train.csv``` — обучающая выборка с ```target```;
- ```data/test.csv``` — тестовая выборка без ```target```;
- ```data/events.csv.gz``` — события для построения признаков;

Одна строка в ```train.csv``` и ```test.csv``` соответствует одной ```cookie_id``` с заданным суточным окном наблюдения.

**train.csv и test.csv**

В этих файлах содержатся метаданные куки и границы окна наблюдения:
- ```cookie_id``` — идентификатор куки;
- ```cookie_created_at``` — время первого появления куки, которое может быть раньше начала окна наблюдения;
- ```window_start_ts``` — начало окна наблюдения;
- ```window_end_ts``` — окончание окна наблюдения;
- ```target``` — целевая переменная, есть только в ```train.csv```.

Готовых поведенческих признаков нет — их нужно самостоятельно собрать из событий.

**events.csv.gz**
```events.csv.gz``` содержит историю событий для куки из обучающей и тестовой выборок. Одна строка соответствует одному событию.
- ```cookie_id``` — идентификатор куки;
- ```event_ts``` — время события;
- ```eid```, ```event_name``` — код и название типа события;
- ```platform``` — платформа;
- ```user_agent``` — строка User-Agent;
- ```item_id```, ```item_category```, ```item_location```, ```seller_type``` — идентификатор объявления, его категория, локация и тип продавца;
- ```search_query```, ```search_page``` — поисковый запрос и номер страницы выдачи;
- ```pointer_x```, ```pointer_y``` — координаты курсора в момент события.

События включают просмотры выдачи и объявлений, листание фотографий, переходы на страницу продавца, контактные действия, добавление в избранное, вход в аккаунт и показ капчи. Некоторые поля заполнены только для определённых типов событий или платформ.

**Target**

```target = 1``` — кука из трафика известных сервисов автоматизированного сбора данных.

```target = 0``` — кука из трафика, отнесённого к человеческому.

Для каждой ```cookie_id``` нужно предсказать ```score``` от 0 до 1: чем выше значение, тем вероятнее, что кука принадлежит боту.

Признаки должны быть доступны на момент окончания окна наблюдения.  


**Допускается использование:**

1. Классических ML-моделей.
2. Правил и эвристик.
3. Гибридных подходов.
4. Open-source моделей (<= 1B параметров) и библиотек, которые запускаются локально и не обращаются к внешним API.

### Формат решения и используемая метрика

Файл с предсказаниями должен содержать ровно две колонки:

- ```cookie_id``` — идентификатор куки из ```test.csv```;
- ```score``` — число от 0 до 1, чем выше, тем вероятнее, что кука принадлежит боту.

Для каждой ```cookie_id``` из ```test.csv``` должна быть ровно одна строка. Пропуски, дубликаты и дополнительные куки не допускаются.

Пример формата есть в ```sample_submission.csv```.

Основная метрика — **Precision при Recall ≥ 70%** на скрытой тестовой выборке. Она рассчитывается по кукам, а не по отдельным событиям.

Среди всех порогов, при которых модель находит не менее 70% ботов, выбирается порог с максимальным precision. Чем выше доля настоящих ботов среди отмеченных куки при выполнении требования по полноте, тем лучше результат.

Дополнительно могут показываться PR-AUC и ROC-AUC. Они используются для диагностики, но итоговый score на платформе считается по Precision при Recall ≥ 70%.

## Решение

### Структура проекта

```
├── notebooks/
│   ├── EDA.ipynb          очистка событий, утечка за окном, схема валидации, baseline из quickstart
│   ├── baseline.ipynb     baseline на базовых агрегатах и поведенческие признаки по гипотезам, абляция групп
│   ├── experiments.ipynb  проверка модификаций: признаки для мобильных ботов, отбор признаков, модели и блендинг
│   └── solution.ipynb     итоговое решение: признаки, валидация, обучение, submission.csv
├── bot_detection_challenge/
│   ├── data/              train.csv, test.csv, events.csv.gz
│   ├── metric.py          официальная метрика Precision@Recall≥0.7
│   └── quickstart.ipynb   стартовый ноутбук из задания
├── pyproject.toml         зависимости
└── uv.lock                зафиксированные версии
```

Ноутбуки идут в порядке работы: EDA → baseline → experiments → solution. Основной — `notebooks/solution.ipynb`. Он самодостаточен: от сырых данных до `submission.csv`. Решения в нём опираются на предыдущие ноутбуки, там же подробности.

### Запуск

Python 3.11, зависимости через [uv](https://docs.astral.sh/uv/):

```bash
uv sync
uv run jupyter nbconvert --to notebook --execute --inplace notebooks/solution.ipynb
```

Ноутбук пишет `submission.csv` в корень репозитория. Версии библиотек зафиксированы в `uv.lock`, сид — `SEED = 42`, повторный запуск даёт тот же файл. Прогон занимает около 5 минут.

### Подход

**Очистка** (`EDA.ipynb`). Берём только события внутри окна куки. В train есть события после окна (у ботов 42% событий, у людей 11%), а в test их нет. Без фильтра признаки quickstart дают 0.43 вместо 0.09, и весь этот прирост — утечка. Удаляем полные дубликаты (1.5%, артефакт логирования) и `eid`, приводим `platform` к трём значениям. Пропуски в основном структурные (например, на мобильных нет курсора), их не заполняем: бустинги работают с NaN.

**Признаки** (`baseline.ipynb`, `experiments.ipynb`). 76 агрегатов по событиям куки в её окне. Каждая группа проверяет гипотезу о поведении бота:
- тайминги — бот работает ровным циклом с короткими паузами;
- курсор — бот двигает курсор в узкой области мелкими шагами;
- всплески — много действий за минуту;
- поиск — бот листает выдачу глубоко и повторяет запрос;
- разнообразие — мониторинг цен обходит много городов в одной категории;
- мобильные — боты в приложении выгружают контакты продавцов;
- базовые счётчики, переходы между событиями, User-Agent.

Связь признака с таргетом оценивали одномерным ROC-AUC, вклад групп — абляцией. Сильнее всего работают тайминги и курсор. User-Agent разбираем на тип клиента, ОС и версию, а категориальные признаки передаём моделям как категории. Из пар дублей (корреляция Спирмена > 0.95) оставлен один признак.

**Валидация.** Test идёт после train, поэтому валидация по времени: 4 фолда по 2 дня с обучением на предыдущих днях и отдельный сплит с горизонтом в неделю, как у test. Метрика считается официальным `metric.py`, к ней добавлен 95% бутстрап-интервал. Adversarial validation даёт ROC-AUC 0.50, то есть дрейфа между train и test нет.

**Результаты** (P@R0.7 по OOF-предсказаниям 4 фолдов, в скобках 95% интервал):

| Шаг | Модель | P@R0.7 |
|---|---|---|
| baseline | quickstart (RandomForest, 2 признака) | 0.09 [0.08, 0.11] |
| baseline | CatBoost на базовых агрегатах | 0.23 [0.20, 0.29] |
| модификация | CatBoost на поведенческих признаках (`baseline.ipynb`) | 0.77 [0.70, 0.81] |
| модификация | **блендинг CatBoost + LightGBM** (`solution.ipynb`) | **0.77 [0.70, 0.84]** |

Основной прирост дали поведенческие признаки. Модификации из `experiments.ipynb` (признаки для мобильных ботов, отбор признаков, другие модели) не выходят за доверительный интервал. В итоговое решение взят блендинг: по качеству он на уровне лучших вариантов и меньше зависит от сида. На сплите с горизонтом как у test — 0.76 [0.66, 0.83].

**Что не сработало:** проверка хронологии по объявлениям (`item_id` соседних событий не связаны даже у людей), отдельные модели для web и мобильных, подбор гиперпараметров — всё в пределах шума.

**Ограничения**
- Мобильных ботов модель находит хуже, чем web (recall ~0.57 против ~0.78): на мобильных нет курсора.
- P@R0.7 на ~100 ботах в фолде шумит на ±0.03, поэтому варианты сравнивали по нескольким сидам и доверительным интервалам.
- User-Agent легко подделать: новые сервисы ботов могут обходить эти признаки.

### Использованные библиотеки

pandas, numpy, scikit-learn, CatBoost, LightGBM, SciPy — все open-source, запускаются локально.
